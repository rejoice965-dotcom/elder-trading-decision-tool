【问题 1（最重要）：JS↔Python 数值对照表不可信，必须重做】
====================================================================

验收方用三种独立方式复核了 2026-11-16（600519.SH，akshare 缓存
data/cache/600519_SH_daily_qfq.csv + daily_raw.csv）：

- elder_indicators（pandas）输出：EMA13 1418.697773、MACD DIF 35.709194、
  DEA 36.120430、柱 -0.411236、RSI14 **65.173166**、Force Index **71004743.4253**、
  触发价 1437.70（T-1 raw high 1437.69 + tick 0.01）✓。
- 用 Python **逐行复刻 engine.js 算法**（ewm span 语义、alphaEwm 1/period、
  同一份 akshare 序列）输出：EMA13 1418.697773、RSI14 **65.173166**、FI **71004743.4253**
  ——与 elder_indicators 完全一致。
- 而 P5 交付的对照表写的是 RSI14 **62.358828**、FI **64017254.2759**：
  既对不上 elder_indicators，也对不上 engine.js 在同一数据上的输出。

⇒ 结论：P5 对照表里的 RSI/FI 两列来自**另一份数据口径**（疑似腾讯 qfq 实时序列），
「JS 与 Python 对照一致」实为同一口径自证，验收无效。

修复要求：
1. 对照必须用**同一份固定输入**：把 `data/cache/600519_SH_daily_qfq.csv` 的
   date/open/high/low/close/volume 序列导出为 JSON，作为唯一测试输入。
2. 两侧分别计算：（a）`elder_indicators` Python（load_config + calculate_indicators，
   参数取 docs/indicators.yaml）；（b）`presentation/query/engine.js` 的 calculate
   （用 Node 直接跑，或在报告中贴等价复刻脚本）。两侧吃**同一份 JSON**。
3. 逐项对照：EMA13、MACD DIF/DEA/柱、RSI14、Force Index、Elder-Ray bull/bear、
   Stochastic K/D、第 1 重方向、第 2 重 setup、第 3 重触发价。
   标准：数值相对误差 < 0.5%，**布尔判定 100% 一致**。
4. 若对照发现 JS 公式与 pandas 有实质差异（种子、边界、NaN 处理），
   **以 elder_indicators（pandas）为准修复 JS**，不得反过来改 Python。
5. 把对照脚本提交进仓库（如 `scripts/compare_js_engine.py` + 输入导出），
   保证以后可复跑，不要只贴一次性的表。

====================================================================
【问题 2：腾讯成交量单位是「手」，必须换算成「股」】
====================================================================

腾讯 fqkline 返回的 volume 单位是手（实测 2022-01-04 腾讯 33843 手 = akshare 3384262 股），
而 `elder_indicators` / 2% 仓位的口径是股。当前 app.js 直接 `volume:number(bar[5])`，
未 ×100 → 用腾讯数据时 Force Index 与任何成交量相关展示都差 100 倍。

修复：解析腾讯数据处统一 `volume = number(bar[5]) * 100`，
并在代码注释与页面数据声明里注明「腾讯接口量纲为手，已换算为股」。

====================================================================
【问题 3：数据源口径差异要如实声明（不阻塞，但要写清楚）】
====================================================================

腾讯 qfq 与 akshare qfq 的复权因子不同（2022-01-04 腾讯收 1828.29 vs akshare 1772.94，
差约 3%；近期收敛）。这会导致：线上页面的指标/信号与项目回测缓存（akshare）在
远端历史与 RSI/FI 上存在细微口径差异。

修复：在页面固定角落声明追加一句：
「线上指标基于腾讯前复权口径，与项目回测缓存（akshare 前复权）可能存在细微差异；
判定阈值（30/70、突破价）不受影响」。
**不要**试图在页面端做复权对齐，那是二期的事。
